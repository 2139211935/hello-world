# 概念库 · 使用说明

本库存放**概念 MOC（地图）页**：一个概念一个文件，是"重内聚"的中枢 —— 用 dataview 把分散在 `00-知识库/原子库/` 的原子点自动聚合起来，并反向列出引用了本概念的**主题索引（00-知识库/笔记库）**。自身**不承载完整知识点正文**，只做聚合与导航。

> [!warning] 概念 ≠ 主题索引 —— 分界铁律
> - **概念（本库）＝名词本体/分类锚点**：一个既定**名词**（如 特征阻抗、反射、串扰、抖动、眼图），只**聚合导航**，**不写叙事正文**。回答"这个概念有哪些原子点"。
> - **主题索引（笔记库）＝聚合入口/货架**：按一个**主题/角度**把相关原子点**列出来**，**只列不展开**。回答"这个主题拢了哪些点"。讲清道理靠原子点自身的"讲懂型正文"与概念聚合，不再额外成文。
> - **命名规则**：概念名必须是**名词**；出现"为什么/如何/为什么需要/是什么"等疑问句或叙事句式 → **不是概念，是索引/目录的一节**，去笔记库，不做概念、也不写展开成文。
> - **概念定位规则**：只写**一句话名词定义 + 覆盖边界**。**禁止**因果链（"因为…所以…"）、比喻、引导句（"我们先看…"）、行文衔接。叙事推进去原子点正文或主题索引。
> - **不同层、不同轴**：概念是"静态名词"，主题索引是"聚合入口"。概念页不要说"从……到……"的故事；主题索引不是叙事文章，只做导航。
> - 口诀：**这是"一个东西/名词"还是"一个主题的货架"？** 前者留本库，后者去笔记库；名词用名词命名，主题货架按主题列点（不展开）。

> 三层架构：原子（00-知识库/原子库）→ 概念（本库）→ 主题索引（00-知识库/笔记库）。概念页是**概念轴**聚合，主题索引是**主题轴**列点，两者可交叉点到同一批原子点。

## 文件命名

文件名 = 概念名，同时是原子笔记 `concept` 字段的值（去 `.md`）。
示例：`欧姆定律.md`、`参考方向.md`。

## frontmatter 字段

```yaml
---
type: 概念
概念: <概念名>
日期: 2026-08-30
状态: 进行中        # 待完善 / 进行中 / 已完善
tags: []
---
```

## 正文结构

1. `# 概念名`
2. `> [!info] 概念定位` —— 一句话名词定义 + 覆盖的知识边界。**只写名词解释与边界**，禁止因果链/比喻/引导句/行文衔接。
3. `## 原子点库（自动重内聚）` —— dataview 聚合属于本概念的原子点（见下）。
4. `## 引用本概念的主题索引（自动反链）` —— 反向列出用到本概念的外部索引，**含 00-知识库/笔记库/ 的主题索引**。
5. `## 相关概念` —— 手列相邻/上下游概念。

## dataview 重内聚（从 00-知识库/原子库 聚合）

````
```dataview
TABLE 状态, 日期, file.link AS 原子点
FROM "00-知识库/原子库"
WHERE concept = "<概念名>"
SORT 状态 ASC
```
````

## 概念反链（列出引用了本概念的主题索引）

````
```dataview
TABLE file.link
FROM ""
WHERE contains(file.outlinks, [[<概念名>]])
```
````

> 主题索引或 `00-知识库/笔记库/` 凡引用某概念，用 `[[概念名]]` 引用即可被上表统计（**主题索引也走此反链**）。若索引量大导致性能吃紧，可在 `FROM` 里限定范围，如 `FROM "电路原理" OR FROM "00-知识库/笔记库"`。
